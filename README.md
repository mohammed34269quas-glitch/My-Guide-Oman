# دليلي عُمان

منصة تربط السياح بالمرشدين السياحيين في محافظات عُمان الإحدى عشرة.

> للشرح التفصيلي خطوة بخطوة (تفعيل Firebase، التجربة المحلية، النشر، الأخطاء الشائعة) اقرأ `دليل_الربط_والنشر.md`.

## ما الذي تغيّر

- **سبب عدم عمل التسجيل:** ملف `firebase-config.js` كان فارغاً، فلم يتصل الموقع بمشروع Firebase. تمت تعبئته من إعدادات مشروعك `my-guide-oman`، وحُذفت كتلة Analytics المكررة من `index.html`.
- **الملفات:** تم فصل الشيفرة إلى `app.js` (الحسابات) و`features.js` (الخريطة والمرشدون والرحلات) بدل الشيفرة المضمنة، ليتمكن CSP من منع السكربتات غير المعروفة.
- **الخريطة:** رسم تقريبي لعُمان بصيغة SVG داخل الصفحة نفسها (بلا صور أو مكتبات خارجية)، عليه المحافظات الإحدى عشرة؛ تضغط على أي محافظة فتظهر أماكنها وعدد مرشديها.
- **المرشدون:** بطاقات بالاسم والتقييم واللغات والمناطق والسعر، وكلها حسابات حقيقية. لا توجد بيانات تجريبية. يظهر المرشد بعد أن يعتمده المدير ويكمل ملفه (السعر والمناطق)، وتُعرض القائمة للمسجّلين فقط.
- **رحلة بطلب سائح:** يختار السائح المحافظة والمكان والتاريخ وعدد الأشخاص ومرشداً معتمداً، فيقبل المرشد أو يرفض.
- **رحلة ينظمها مرشد:** ينشر المرشد رحلة بعدد مقاعد وسعر للشخص، ويطلب السياح الانضمام، والمرشد وحده يختار من يقبل.
- **التقييم:** بعد اكتمال الرحلة يقيّم السائح المرشد مرة واحدة.
- **الإدارة:** المدير يعتمد طلبات المرشدين من الصفحة نفسها بعد مراجعة الترخيص.

## التفعيل

1. في Firebase Console: Authentication ثم Sign-in method ثم فعّل **Email/Password**.
2. أنشئ قاعدة **Firestore** إن لم تكن موجودة.
3. ثبّت الأداة وانشر القواعد والموقع:

   ```sh
   npm install -g firebase-tools
   firebase login
   firebase use my-guide-oman
   firebase deploy --only firestore:rules,hosting
   ```

4. سيظهر الرابط: `https://my-guide-oman.web.app`. يمكنك ربط نطاقك الخاص من Hosting ثم Add custom domain.

## أول مدير (ضروري لاعتماد المرشدين)

1. سجّل في الموقع **حساب سائح** عادياً بالبريد الذي ستديره به.
2. في Authentication ثم Users انسخ **User UID** لهذا الحساب.
3. في Firestore أنشئ مجموعة `admins`، ووثيقة معرّفها هو الـ UID، وبداخلها أي حقل (مثل `ok: true`).
4. سجّل الدخول بهذا الحساب: ستظهر لوحة «الإدارة» أسفل لوحة السائح.

## تجربة الدورة كاملة

1. سجّل حساب مرشد (رقم ترخيص تجريبي)، ثم اعتمده من حساب المدير.
2. سجّل دخول المرشد، واملأ «ملفي» (السعر والمناطق)، وانشر رحلة.
3. بحساب سائح آخر: اطلب رحلة من المرشد، أو اطلب الانضمام لرحلته.
4. المرشد يقبل ثم يضغط «تمت الرحلة»، فيظهر للسائح زر التقييم.

## الأمان

- قواعد Firestore ترفض كل شيء افتراضياً، وكل مجموعة تقبل حقولاً محددة بأنواع وأطوال محددة.
- لا يستطيع أحد تغيير دوره، ولا اعتماد نفسه مرشداً، ولا تعديل تقييمه أو تقييم غيره.
- رقم الترخيص والهاتف يقرؤهما المدير فقط.
- طلبات الانضمام والرحلات الموجهة لا يراها إلا أطرافها.
- Hosting يضيف الترويسات: Content-Security-Policy وHSTS وX-Frame-Options وغيرها.
- الشيفرة تهرّب كل نص قادم من المستخدمين قبل عرضه.
- المصادقة لا تحمّل إطارات أو سكربتات Google الإضافية.

### خطوات يجب أن تنفذها أنت

1. **قيّد مفتاح API:** Google Cloud Console ثم Credentials ثم المفتاح ثم HTTP referrers، وأضف `my-guide-oman.web.app` و`my-guide-oman.firebaseapp.com` ونطاقك.
2. فعّل **App Check** لـ Firestore وAuthentication لتقليل الاستخدام الآلي.
3. فعّل Email enumeration protection وسياسة كلمات المرور القوية من إعدادات Authentication.
4. فعّل تنبيهات الميزانية في Google Cloud.
5. اختبر القواعد بـ Firebase Emulator قبل الإطلاق للجمهور.

## حدود النسخة الحالية

- لا توجد دردشة ولا دفع إلكتروني. عند إضافة الدفع استخدم صفحة دفع مستضافة من مزود معتمد، ولا تخزّن بيانات البطاقات.
- التقييمات تُحسب في المتصفح من وثائق التقييم. عند كثرة البيانات انقلها إلى Cloud Functions.
- السعر المعروض إرشادي (لليوم)، والاتفاق النهائي بين السائح والمرشد.
- لا ترفع صور الهوية أو الترخيص إلى قاعدة بيانات عامة. يراجع المدير الترخيص خارج المنصة حالياً.
- الخريطة رسم تقريبي للتوضيح، وليست مرجعاً جغرافياً دقيقاً ولا تعرض الطرق.

## ملف `ads.txt`

ملف `ص.txt` الذي أرفقته هو سطر `ads.txt` لـ Google AdSense، لذلك أُعيدت تسميته إلى `ads.txt` ووُضع في جذر الموقع. هذا الملف وحده لا يعرض إعلانات؛ تحتاج موافقة AdSense وإضافة سكربت الإعلان، وسيتطلب ذلك تعديل CSP في `firebase.json`.
